# Contributing to quorum-rs

Thanks for taking the time. This file documents the conventions the
release tooling already enforces — following them up front saves a
CI round-trip.

## Workspace Structure

Cargo workspace with three crates. `quorum-rs` is both a library
(SDK + reference runtime) and a binary (`quorum` CLI) shipped in
the same crate so `cargo install quorum-rs` gives you the CLI and
`cargo add quorum-rs` gives you the SDK.

| Crate | Path | Role |
|---|---|---|
| `quorum-rs` | `crates/quorum-rs/` | SDK + reference runtime + `quorum` CLI (`run` / `status` / `trace` / `tui` / `init` / `redeem`). |
| `llm-repair` | `crates/llm-repair/` | JSON-repair, markdown-extraction, and tool-call recovery for malformed LLM output. |
| `quorum-crypto-core` | `crates/quorum-crypto-core/` | Ed25519 / secp256k1 / SHA3 primitives + audit envelope. Optional dep of `quorum-rs` (`audit` feature). |

Topological dep order (used by the release-publish workflow):
`llm-repair` → `quorum-crypto-core` → `quorum-rs`.

## Commit Messages

Every commit must follow [Conventional Commits](https://www.conventionalcommits.org/).
This is what drives the automated version bump in
`release-prepare.yml` and the changelog generated by `git-cliff`.

```
<type>(<optional scope>): <description>

[optional body]

[optional footer(s)]
```

### Types and Release Impact

| Type | Description | Release Impact |
|---|---|---|
| `feat` | New feature | **Minor** bump (0.1.0 → 0.2.0) |
| `fix` | Bug fix | **Patch** bump (0.2.0 → 0.2.1) |
| `perf` | Performance improvement | **Patch** bump |
| `refactor` | Code change that neither fixes a bug nor adds a feature | **Patch** bump |
| `docs` | Documentation only | Changelog only |
| `test` | Adding or correcting tests | Changelog only |
| `ci` | CI/CD changes | Changelog only |
| `build` | Build system or external dependencies | Changelog only |
| `style` | Formatting, missing semicolons, etc. | Changelog only |
| `chore` | Other changes that don't modify src or test files | Changelog only |
| `revert` | Reverts a previous commit | Changelog only |

### Breaking Changes

Append `!` after the type/scope:

```
feat!: redesign agent protocol
fix(orchestrator)!: change NATS subject format
```

Or use a `BREAKING CHANGE:` footer in the body:

```
feat: redesign agent protocol

BREAKING CHANGE: AgentContext now requires a session_id field
```

Either form bumps the major version (0.2.1 → 1.0.0). The release
workflows look at both the subject `!` shorthand AND the body
footer, so footer-only breaking changes also trigger the major
bump.

### Examples

```
feat: add user message injection to deliberations
fix(orchestrator): handle NATS reconnect on timeout
docs: update API endpoint documentation
test: add evaluator round-trip tests
ci: split CI into parallel jobs
refactor(agents): extract prompt builder into module
perf: batch KV reads in history retrieval
```

### Enforcement

- **CI** — `commit-lint.yml` (the "Validate PR Title" check) runs on
  every PR. If the PR title isn't conventional but a commit on the
  branch is, the workflow auto-edits the PR title to match. If
  nothing on the PR is conventional, the check fails with guidance.
- **Local hook** (optional) — wire `scripts/commit-msg-hook.sh` into
  your `.git/hooks/commit-msg` for the same validation pre-push.
  Skipped automatically on `release/*` branches since those are
  generated by `release-prepare.yml`.

## Branch Workflow

```
{issue#}-{description}  ──merge──▶  dev
```

1. Open or pick an issue, then branch off `dev`: `4-port-release-workflows`.
2. Make changes with conventional commit messages.
3. Open a PR targeting `dev` with a conventional commit title
   (the `commit-lint` check will auto-fix it if you forget, as
   long as the PR has at least one conventional commit).
4. Merge to `dev`. CI must be green; coderabbit's review is
   advisory but typically addressed before merge.

`dev` is the default and only long-lived branch. Tags serve as
immutable release references — `vX.Y.Z` for workspace-wide
releases, `<crate>-vX.Y.Z` for per-crate releases.

## Release Process

Releases are dispatched manually from the Actions tab (or via
`gh workflow run …`). The relevant workflows live in
`.github/workflows/`; consult their headers for arguments and
behaviour. The shape of the process below is stable regardless of
file naming.

### Stable releases (crates.io)

1. **Prepare** — dispatch the `Prepare Release` workflow with
   `crate` ∈ `{all, llm-repair, quorum-crypto-core, quorum-rs}`.
   It computes the next semver from conventional commits since
   the last matching tag, runs `cargo set-version`, regenerates
   `CHANGELOG.md`, and opens a `release/<crate>/v<X.Y.Z>` PR
   against `dev`. Workspace-wide releases (`crate=all`) refuse
   to start when sibling crates have drifted to different
   versions — bump them to a common baseline first.
2. **Human review** — edit `CHANGELOG.md` on the release branch
   if entries need rewording.
3. **Merge the release PR** — the `Publish Release` workflow
   fires on merge: it tags the merge commit, publishes the
   affected crate(s) to crates.io in topological order (polling
   for the specific version on the index between hops so
   siblings can resolve), then cuts a GitHub Release.

Tag naming:
- Per-crate: `<crate>-vX.Y.Z` (e.g. `llm-repair-v0.7.0`)
- Workspace-wide: `vX.Y.Z`

### Pre-releases (RC / alpha / beta)

The `Pre-Release` workflow dispatches on a pre-release tag like
`quorum-rs-v0.7.0-rc.1` or `v0.7.0-rc.1`. The Cargo.toml bump
happens on a **transient** branch that's never pushed to `dev`
(so RC iterations don't pollute release history), the tag is
force-pushed (pre-release tags are mutable — iterate on the same
`-rc.N` during validation), the pre-release version is published
to crates.io, and a GitHub Pre-Release is created.

Stable semver is refused on the pre-release path to keep the
stable flow exclusive to `Publish Release`.

### Preview (no side effects)

A preview workflow renders what `Prepare Release` would do
(version bump + changelog) into the run's step summary, without
touching `Cargo.toml` or opening a PR.
